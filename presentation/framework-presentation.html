Test data

10 / Worker isolation

Mỗi worker sở hữu một user runtime riêng.

Tạo duy nhấtEmail và phone ngẫu nhiên được đăng ký qua API cho từng parallelIndex.
File tạm có định danhTimestamp đến mili-giây + worker + PID ngăn trùng tên.
Dọn sau khi chạyFixture xóa đúng file trong finally; không lưu credential vào repository.
// baseTest.js · worker scope
workerUserData: [async ({}, use, info) => {
  const runtime = await createRuntimeUserData(
    info.parallelIndex
  );
  try {
    await use(runtime);
  } finally {
    await removeRuntimeUserData(runtime.filePath);
  }
}, { scope: 'worker' }]
test-results/runtime-users/[timestamp]-worker-[index]-pid-[pid].json10

Element & locator

11 / Inspect

Nhìn element theo ý nghĩa người dùng, không theo CSS trang trí.

Mở DevTools bằng F12 hoặc dùng Pick Locator trong Playwright UI Mode; kiểm tra role, accessible name, label, placeholder và test id.

Sau khi xác nhận locator ổn định, đặt nó trong constructor của Page Object và bọc thao tác thành method nghiệp vụ.

getByRole('button', { name: ... })
getByLabel() / getByPlaceholder()
getByTestId()
getByText()
CSS ngắn, có scope rõ ràng
XPath — chỉ khi không có lựa chọn tốt hơn
Ví dụ: LoginPopup.phoneInput → fillPhone()11

18 / Lệnh chạy multi-worker

🧪
node --test core/reporters/*.test.jsKiểm tra report tổng và report tách theo worker
🌐
$env:PW_WORKERS=4; npx playwright test ... --repeat-each=4Ví dụ phân 4 instance cho tối đa 4 worker độc lập
💼
npx playwright test --project="Apply Job Tests"Chạy riêng business flow ứng tuyển

npm run reportMở report tổng; thư mục workers chứa report riêng
